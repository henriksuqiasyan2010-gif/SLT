# ASL Translator — project notes for Claude Code

Read `PHASES.md` (the plan) and `STATUS.md` (progress) at the start of every session.

## Global invariants

- **One feature function.** `asl.features.extract()` is the only code that turns landmarks into model input. Kaggle kernels and the app import the same module. Never duplicate it.
- **Feature version.** `FEATURES_VERSION` in `features.py` is saved into model metadata. The app refuses to load a model trained with a different version.
- **Landmark format.** One frame = float32 array `(543, 3)` (x, y, z) in the same order as the dataset, missing points = NaN. A clip = `(T, 543, 3)`.
- **Performance:** at least 15 FPS with Holistic on the user's laptop, one model inference under 50 ms on CPU, the UI never freezes.
- **Tests:** every module in `src/asl/` has tests in `tests/`. `pytest` passes before every commit. Tests never need a camera or network: they use `data/sample/` and recorded `.npy` clips.
- **Config:** constants in `src/asl/config.py`, user settings in `settings.json`, no magic numbers in code.
- **Errors:** the user sees a clear message in the UI; details go to `logs/`.
- **Dependencies:** pinned in `requirements.txt`. PyTorch is used only on Kaggle; the app uses onnxruntime.

## Environment

- Python 3.11 in `.venv` (`.venv\Scripts\python`). Run tests with `.venv\Scripts\python -m pytest`.
- `src/` layout: tests add `src/` to `sys.path` via `tests/conftest.py`; scripts do the same at the top.
- The app starts with `.venv\Scripts\python -m asl.app` from any folder: `.venv\Lib\site-packagessl-src.pth` holds the absolute path of `src/` (an editable `pip install -e .` would need the `wheel` package, not installed). Recreate the file if `.venv` is rebuilt.
- Kaggle auth: user-level environment variable `KAGGLE_API_TOKEN` (never printed or copied).

## Dataset facts (verified)

- Row order inside every frame is constant: face 468, left_hand 21, pose 33, right_hand 21 (tested in `tests/test_landmarks_io.py`), so `pd.read_parquet(..., columns=[x, y, z]).reshape(-1, 543, 3)` is valid.
- A hand that is not detected is NaN for all 21 points of that frame. In the 30 sample clips only one hand is ever detected at a time (never both); the resting hand is NaN while its pose wrist/finger points (15-22) are still present. Feature extraction and the segmenter must not treat a missing hand as an error.
- Pose wrists (15, 16) are present in every frame of the sample.
- Full dataset (kernel `asl-stats`, `reports/stats/`): 94,477 clips, 250 signs, 21 participants; 299-415 clips per sign (median 381.5); every parquet has a multiple of 543 rows; no clip without hands; frame numbers are contiguous in 99.95% of clips.
- **Clip length (frames): median 22, mean 37.9, p75 44, p90 92, p95 135, p99 219, min 2, max 537.** Frames with a detected hand: median 15, p90 54. Phase 2 `T_FIX` is chosen from this (about the median, multiple of 8 → 24; check against p75 = 44 before fixing it).
- Dominant hand: right in 57.5% of clips, left in 42.4% — handedness cannot be ignored (Phase 2 decision). Full dataset; dominant = hand detected in more frames (0.13% ties).
- Both hands (full dataset, from per-clip `left_frames`/`right_frames`/`hand_frames` in `reports/stats/stats.csv`): 95.8% of clips only ever show one hand; 4.2% (3,993) show both hands at some point; 2.5% (2,402) have at least one frame with both hands at once; only 0.5% of all hand frames have both hands. So "one hand per clip" is the norm but not a rule — features must handle both hands present.

- **Frame aspect ratio: the dataset videos are portrait, mostly 3:4 (width/height 0.75); our camera is landscape 4:3.** Not documented; estimated from face proportions (eye-mouth height / interocular distance) and from eye-mouth height / shoulder width, against our 640x480 recordings (0.974 and 0.297). Kernel `asl-check` (`reports/check/`), all 21 participants: face ruler median 0.749, IQR 0.73-0.81; 18 participants within 8% of it. Three deviate > 15% on **both** rulers (so camera, not anatomy): 30680 (0.505 / 0.525), 62590 (0.628 / 0.646), 32319 (0.909 / 1.059) -> `config.DATASET_ASPECT_BY_PARTICIPANT` {30680: 0.485, 62590: 0.600, 32319: 0.923}, everyone else 3/4; `features.dataset_aspect(pid)`. Without the correction vertical motion relative to shoulder width would be ~1.8x larger in our recordings than in the dataset.
- Gesture length: dataset clips are cut tightly around the sign (trimming frames without hands removes only 1% of frames in the 30 sample clips); median clip length hello 20, please 30, mom 21 frames (~0.7-1.0 s if the dataset is 30 fps, which is an assumption).

## Features (`src/asl/features.py`)

`extract(clip, t_fix=config.T_FIX, aspect=config.DATASET_ASPECT) -> (features (t_fix, F) float32, mask (t_fix,) bool)`.
**Callers outside the dataset must pass `aspect=config.CAMERA_ASPECT`** (or `capture.recording_aspect(meta)`); dataset callers pass `features.dataset_aspect(participant_id)`.
**Live clips are cut with `trim_idle(clip, fps, aspect)` first and a still second hand is dropped (`keep_moving_hand`, `config.LIVE_KEEP_MOVING_HAND`):** `s, e = trim_idle(clip, fps, aspect); extract(keep_moving_hand(clip[s:e], aspect), aspect=aspect)` — this is `SignModel.predict_clip`. Training does NOT use `trim_idle` (see Decisions) - dataset clips are already cut around the sign by its authors.

**`FEATURES_VERSION = 1`** means exactly this pipeline (a version 2 with `keep_moving_hand` as step 0 was trained in Phase 4 and not kept, see Decisions):
1. y / aspect (y in units of the image width); 2. trim leading/trailing frames without any hand;
3. centre = median shoulder mid-point, scale = median shoulder width (fallback without shoulders: mean of the available subset points, `FEATURES_FALLBACK_SCALE_K` x their median distance from it);
4. dominant hand = more frames visible, tie -> right; left-dominant clips are mirrored in x with all left/right pairs swapped (hands, pose 11-22, eyes, lips, nostrils), so the dominant hand is always in the right-hand slot;
5. 130-point subset (left hand 21, right hand 21, pose 11-22, lips 40, nose 4, eyes 32) resampled to `t_fix` by linear interpolation in time;
6. velocity = frame difference after step 5, on positions smoothed with a Gaussian (`FEATURES_VELOCITY_SMOOTH_SIGMA` = 2 grid steps);
7. NaN -> 0. Per frame: positions 260 | velocity 260 | hand present (dominant, other) 2 | fingertip distances 10 + 10 => **F = 542** (x, y only; `FEATURES_USE_Z = False`).
The mask is all True for a non-empty clip, all False for an empty one.
Any change of the output for the same input -> bump `FEATURES_VERSION`.
